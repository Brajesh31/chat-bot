# 🏛️ Project Governance

This root-level file is the entry point for repository governance. The detailed governance policy and change-review principles are maintained in [docs/GOVERNANCE.md](docs/GOVERNANCE.md).

## Decision ownership

- The repository owner and maintainers govern project scope, public behavior, release decisions, and security response.
- [CODEOWNERS](CODEOWNERS) defines the current review-routing rule.
- [MAINTAINERS.md](MAINTAINERS.md) records the maintainer process and contact path.
- GitHub repository permissions determine actual access.

## Community and contribution policies

- [Code of Conduct](CODE_OF_CONDUCT.md)
- [Contribution Guide](CONTRIBUTING.md)
- [Support Policy](SUPPORT.md)
- [Security Policy](SECURITY.md)

## Project principles

1. Document the behavior that exists in source code.
2. Label proposed functionality as proposed.
3. Preserve existing source and assets during maintenance.
4. Review privacy, security, accessibility, dependency, and compatibility impacts.
5. Keep changes small enough to test and review.
6. Do not fabricate screenshots, deployment evidence, certifications, or metrics.
7. Record major technical decisions and their consequences.

## Governance changes

Changes to ownership, license scope, security reporting, or maintainer responsibilities should be reviewed and recorded in the decision log with rationale and an effective date.
