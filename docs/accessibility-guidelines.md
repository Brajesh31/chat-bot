# ♿ Accessibility Guidelines

## Target and honesty

Use WCAG 2.2 AA as a design and review target where applicable. The repository has not completed a formal WCAG conformance audit, so no conformance claim is made.

## Core requirements for this interface

- Provide accessible names for the input and icon buttons.
- Keep all actions keyboard operable.
- Show visible focus.
- Use a meaningful chat region label and polite message announcements.
- Ensure hidden/minimized content is removed from the active accessibility experience as intended.
- Do not rely on color alone to distinguish messages or controls.
- Preserve readable text at zoom.
- Avoid horizontal overflow on narrow screens.
- Respect prefers-reduced-motion.

## Review method

Use keyboard-only navigation, browser zoom, a contrast analyzer, and at least one screen-reader/browser combination. Record exact versions and the behavior observed.

## Reporting

Use the accessibility issue form and include synthetic steps. Do not include private transcripts or credentials. Record the affected task, expected and observed behavior, severity, and owner.
