# 🐛 Bug Reporting

## Before opening an issue

Search existing issues and confirm the behavior is not already documented. Reproduce with synthetic text and a clean reload.

## Required information

- A concise summary.
- Operating system and browser/version.
- Node.js/npm versions when setup/build is affected.
- Exact commit or deployed release, if known.
- Numbered reproduction steps.
- Expected and actual behavior.
- Sanitized console output or screenshot when useful.
- Scope and impact.

## Privacy and security

Do not attach credentials, cookies, access tokens, personal data, or private conversation transcripts. Suspected vulnerabilities must go through the private security reporting route in SECURITY.md, not a public issue.

## Triage

Maintainers should confirm reproduction, severity, affected components, root-cause confidence, mitigation, owner, and regression test. Use the bug triage template for detailed records.
