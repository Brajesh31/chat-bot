# 👤 User Personas

These are project-oriented design personas, not researched demographic profiles. They describe likely user goals and must not be treated as measured audience data.

## Persona A: Frontend learner

**Goal:** Understand how a chat interface connects an input field to component state and rendered messages.

**Needs:** Easy setup, clear file responsibilities, simple examples, and predictable behavior.

**Pain points:** Overly abstract tutorials, missing setup steps, hidden service dependencies, and unexplained rule precedence.

**Success signal:** Can trace a prompt through ChatForm, ChatbotResponse, App state, and ChatMessage.

## Persona B: Beginner contributor

**Goal:** Add a response branch or improve the UI safely.

**Needs:** Contribution instructions, regression examples, coding conventions, and repeatable checks.

**Pain points:** False positives, random tests, stale documentation, and unclear boundaries.

**Success signal:** A focused pull request includes tests, documentation, and evidence.

## Persona C: Maintainer / educator

**Goal:** Keep the demo accurate, safe to teach, and easy to reproduce.

**Needs:** Current architecture, dependency status, known limitations, release checks, and learning materials.

**Pain points:** Claims that imply AI capabilities, undocumented third-party requests, and unverified accessibility statements.

**Success signal:** A fresh checkout passes the automated suite and learners can explain what the application does and does not do.

## Research note

No user interviews, analytics, or quantitative persona research are claimed by this document. Replace or refine these personas only with legitimate, privacy-conscious evidence.
